# サービス別の集中学習

特定のクラウドサービス・ミドルウェア(例: Azure Service Bus)を主役にして、そのサービスが活きる状況ごとに問題・設計を行う
`projects/` や `quiz/` がシステム全体を主役にするのに対し、ここでは対象サービスの機能・仕様・トレードオフを深く理解することを目的とする

## フォルダ構成

- サービスごとにフォルダを分ける: `services/<サービス名>/`(英小文字のケバブケース、例: `azure-service-bus`)
- 各サービスフォルダの構成
    - `README.md`: 学習の概要と進捗
        - 先頭に以下のフロントマターを付ける
            - `summary`: 対象サービスの概要(1文)
            - `category`: 種類(メッセージング / DB / コンピュート / ネットワーク / ID など)
            - `status`: 進捗(着手 / 学習中 / 一通り完了 など)
        - 「機能マップ」として、対象サービスの主要機能・論点を一覧にし、どのシナリオで扱ったかをリンクする(未着手の機能も載せて、学習の抜け漏れが見えるようにする)
        - 似たサービス・競合サービス(例: Storage Queue / Event Grid / Event Hubs)を列挙し、比較シナリオがあればリンクする
    - `scenarios/<連番>-<名前>.md`: 状況ごとの問題と設計(1シナリオ1ファイル)
        - 先頭に以下のフロントマターを付ける
            - `summary`: シナリオの概要(1文)
            - `features`: 主に扱う機能(例: `sessions`, `dead-letter`, `duplicate-detection`)
            - `type`: 種類(下記)
            - `level`: レベル(初級 / 中級 / 上級 など)
        - 構成: `状況` / `問題` / `回答`(ユーザーが書く) / `レビュー`(AI が書く) / `ポイント`(学んだこと)
    - `resource/`: 公式ドキュメントなどの調査結果(機能仕様、制限値、SKU 差、価格など)
        - 勝手にシナリオに特化した結論にしないこと
        - あくまで、ユーザーに質問された内容だけを記載する

## シナリオの種類(`type`)

- `design`: 要件を満たすように対象サービスの機能・設定を選んで設計する
- `selection`: 似たサービスとの使い分け・選定(このサービスを使うべきか/使わないべきか)
- `troubleshoot`: 障害・性能劣化・想定外の挙動の原因を特定して対処する
- `operation`: 監視、スケーリング、SKU・コスト、セキュリティ、DR などの運用設計
- `limits`: 制限値・境界条件(サイズ上限、スループット、タイムアウトなど)に当たる状況への対処
- 該当しない場合は必要に応じて追加する

## 他サービスの扱い

- 対象サービス以外は、役割名で抽象的に扱う(例: 「送信側アプリ」「注文 DB」「ワーカー」「API ゲートウェイ」)
    - 具体的な製品名・設定は原則出さない
    - 例外: 対象サービスとの連携仕様そのものが論点になる場合(例: Azure Functions の Service Bus トリガーのリトライ挙動、Private Endpoint 経由の接続)は具体的に扱ってよい
- 全体構成図は、対象サービスとその周辺の境界だけを描き、他サービスの内部構造には踏み込まない

## 進め方

- AI は出題者・レビュアーとして振る舞う
    - シナリオ作成時は `状況` と `問題` のみを書き、模範解答は書かない
    - ユーザーの回答に対して、`レビュー` で機能の誤解・見落とし・代替案・トレードオフを指摘する
    - 指示があった場合のみ、AI が回答例を書く
- シナリオは、機能マップの未着手機能や、前のシナリオで出た疑問を起点に作る
    - 1シナリオで扱う機能は 1〜3 個程度に絞る
- 仕様・制限値・価格は根拠(公式ドキュメントの URL など)を併記する。SKU やバージョンで挙動が変わるものは前提を明記する
- 図は Mermaid で書く
- 関連する `../projects/` の設計や `../quiz/` の問題があればリンクする

- WEB 検索には `web-lookup` スキルがおすすめ(Azure / Microsoft の公式ドキュメントは Microsoft Learn を優先)
