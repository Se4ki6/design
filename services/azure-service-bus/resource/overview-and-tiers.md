# Azure Service Bus の概要と価格レベル(Tier)

調査日: 2026-10-09

## 概要

- フルマネージドのエンタープライズ向けメッセージブローカー。キュー(1対1)とトピック/サブスクリプション(1対多の Pub/Sub)を提供する
- メッセージは受信側が要求したときだけ届く **pull 型**。ロングポーリングなので、メッセージが来るまで受信操作が待機する
- ブローカーが受け付けたメッセージは3重冗長ストレージに永続化される(ゾーン対応の名前空間なら可用性ゾーンにまたがる)
- 名前空間(Namespace)= キューやトピックを入れるコンテナ。他ブローカーでいう「サーバー」に近いが、実体は巨大クラスタの一部の容量
- 主プロトコルは AMQP 1.0。HTTP/REST も使える。SBMP は 2026-09-30 でサポート終了
- 出典: https://learn.microsoft.com/azure/service-bus-messaging/service-bus-messaging-overview

## Tier の違い

| 項目 | Basic | Standard | Premium |
| --- | --- | --- | --- |
| キュー | ○ | ○ | ○ |
| トピック/サブスクリプション | × | ○ | ○ |
| セッション、トランザクション、重複検出 | × | ○ | ○ |
| リソース | 共有 | 共有(操作数で課金) | 専用の Messaging Unit (MU)。1/2/4/8/16 から選択し、後から変更できる |
| 性能 | - | スループット・レイテンシは変動する | 予測可能 |
| 最大メッセージサイズ | - | 256 KB | 100 MB(AMQP のみ。SBMP/HTTP は 1 MB) |
| VNet / Private Endpoint | × | × | ○ |
| Geo-Replication | × | × | ○ |
| CMK(顧客管理キー) | × | × | ○ |
| JMS | - | 1.1(キューのみ) | 2.0 |
| パーティション | - | エンティティ単位で有効化(16 パーティション) | 名前空間の作成時に指定(全エンティティがパーティション化される) |

- Basic 列の「-」は今回の調査範囲で確認していない項目
- MU の目安: CPU が 25% 未満なら減らす候補、75% 超なら増やす、メモリが 60% 超なら増やす
- MU の課金は1時間単位で、その時間内の最大 MU 数で決まる
- 出典: https://learn.microsoft.com/azure/service-bus-messaging/service-bus-premium-messaging
