# 01. 要件定義(ドラフト)

> AI が叩き台として作成。末尾の「要検討の論点」を決めて確定させる。

## 想定する利用シーン

- 社員が「出張旅費の上限は?」「〇〇システムの障害対応手順は?」のように質問し、回答と根拠文書へのリンクを得る
- 文書の所有部署は SharePoint / ファイルサーバー等に文書を置くだけで、検索対象に自動反映される

## 機能要件

### 必須

1. **チャット**: 自然言語の質問に対し、社内文書を根拠に回答を生成する
2. **出典表示**: 回答に使った文書名・該当箇所・リンクを表示する
3. **会話の継続**: 直前の会話文脈を踏まえた追加質問ができる(マルチターン)
4. **ストリーミング応答**: 生成途中のテキストを逐次表示する
5. **権限トリミング**: ユーザーが閲覧権限を持たない文書は検索・回答に使わない
6. **文書の取り込み**: 文書ソースの追加・更新・削除を検知し、インデックスに反映する
7. **会話履歴**: ユーザーは自分の過去の会話を一覧・再開できる
8. **フィードバック**: 回答に 👍/👎 とコメントを付けられる(品質改善用)

### あれば良い

- 「該当する文書が見つからない」場合に推測で答えず、その旨を返す
- 管理者向けダッシュボード(利用量、コスト、低評価回答の一覧)

## 非機能要件(仮置き)

| 項目 | 目標値(仮) | 前提・根拠 |
|---|---|---|
| 利用者数 | 社員 50,000 人、DAU 10,000 人 | 中〜大企業を想定 |
| 質問数 | 1 人 1 日 5 問 → 50,000 問/日 | ピークは業務時間帯に集中 |
| 文書量 | 100 万文書、平均 10 ページ | 全社規程・手順書・設計書 |
| 初回トークンまでの時間 | p95 3 秒以内 | 検索 + LLM の TTFT を含む |
| 回答完了までの時間 | p95 15 秒以内 | 長文回答を考慮 |
| 文書反映の鮮度 | 更新から 1 時間以内 | 権限変更はより短くすべきか要検討 |
| 可用性 | 99.9%(業務時間) | 社内ツールのため |
| データ所在 | 日本リージョン内 | 社内機密を扱うため |
| セキュリティ | Entra ID による SSO、閉域接続、プロンプト・回答のログ監査 | |
| コスト | LLM 利用料を月額上限で管理 | トークン課金のため |

## 要検討の論点

1. 権限トリミングはどこで行うか(検索時フィルタ / 取り込み時に ACL を埋め込む / 結果の後段チェック)。権限変更の反映遅延はどこまで許すか
2. 文書ソースはどれを対象にするか(SharePoint のみ? ファイルサーバーや Confluence も?)
3. 回答精度をどう測るか(オフライン評価セット、ユーザー評価、出典の正しさ)
4. Azure OpenAI の TPM 上限に達したときの振る舞い(キューイング / 別リージョンへ / 縮退)
5. 会話履歴の保持期間と、ログに機密が残ることへの扱い
6. プロンプトインジェクション(文書に悪意ある指示が埋め込まれる)への対策をどこまでやるか
