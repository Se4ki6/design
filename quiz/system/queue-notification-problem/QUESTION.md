# 問題:通知配信システムの設計(キュー中級〜上級)

- 回答: `answer\system\queue-notification-problem.md`

## 背景

あるSaaSで、ユーザーへの通知(メール/プッシュ/SMS)を送る基盤を作る。
外部プロバイダ(メール・SMS・FCM)はそれぞれ**レート制限と不定期な障害**がある。

## 要件

- ピーク時 5,000 件/秒、平常時 200 件/秒
- 配信は **at-least-once**。ただしユーザーに同じ通知が重複して見えるのは極力避けたい
- 同一ユーザー宛ての通知は**順序を保つ**(例:「注文確定」→「発送済み」)
- 一部プロバイダ(例:SMS)が1時間ダウンしても、他チャネルの配信は遅延させない
- 「パスワードリセット」等の**緊急通知**は、大量のマーケティング通知の後ろで待たされてはならない
- 処理に失敗し続けるメッセージがシステム全体を詰まらせないこと

## 設問

1. キュー構成(トピック/キューの分け方、パーティションキー、優先度の扱い)を図または箇条書きで示せ
2. リトライ戦略とDLQの設計を述べよ。順序保証とリトライはどう両立させるか
3. 重複を抑えるための冪等性をどこでどう実現するか
4. プロバイダのレート制限・障害時に、バックプレッシャーをどう扱うか
5. コンシューマ数をどう決め、何を指標にスケールさせるか
