# 問題: 添付付き問い合わせの受付（初級）

## 背景

Web サイトの問い合わせフォームに、画像や PDF を添付できるようにする。利用者が送信すると受付番号をすぐに表示し、担当者にはメールで知らせたい。メールの送信に時間がかかっても、利用者を待たせたくない。

## 前提と要件

- フォームと受付 API は Azure App Service で動かす
- 問い合わせには氏名、連絡先、本文、最大 10 MB の添付ファイルがある
- 受付記録は担当者が受付番号、状態、作成日時で検索できる
- ピークは 1 分あたり 30 件。通知メールは数分遅れてもよい
- 通知メールが一時的に失敗しても、受付済みの問い合わせは失われない
- 候補として Azure SQL Database、Azure Cosmos DB、Blob Storage、Service Bus、Azure Functions を使える

## 設問

1. フォーム送信から受付番号の表示、担当者への通知までの流れを図か箇条書きで示せ。利用者への応答をどの時点で返すか。
2. 問い合わせの本文・受付状態・添付ファイルをどこに保存するか。RDB、NoSQL、Blob Storage を比較し、今回の規模と検索条件に合う置き場を選べ。
3. メール通知を非同期にする方法を設計せよ。App Service、Service Bus、Functions にそれぞれ何を担当させるか。
4. メール送信に失敗した場合、受付記録と通知処理をどう扱うか。再試行後も失敗する場合の確認方法を示せ。
5. 送信ボタンの連打で同じ問い合わせが2件作られるのを防ぐ、最小限の方法を1つ提案せよ。

## ヒント

- 添付ファイル本体を RDB に入れる必要はあるか。受付記録から添付を探すために何を保存するか
- メール送信の完了と問い合わせの受付完了は、同じ時刻でなければならないか
- キューから同じ通知をもう一度受け取る可能性も考える
