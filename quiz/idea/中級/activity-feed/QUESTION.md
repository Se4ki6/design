# 問題: 利用者の取引履歴フィード（中級）

## 背景

フリマアプリで、購入・発送・受取などの出来事を利用者ごとの時系列画面に表示する。取引そのものは既存の RDB で管理しているが、フィードの表示が遅くなってきた。

## 要件

- 取引 API は App Service。取引の正本は Azure SQL にある
- フィードは利用者 ID と日時で読み、最新 50 件を高速に表示する
- フィードは数十秒遅れてもよいが、取引 DB にない出来事を確定情報として表示しない
- イベントの再配信と、フィードを作り直す運用に対応する
- 候補は Service Bus、Functions、Cosmos DB、Blob Storage、Event Hubs

## 設問

1. 取引 DB を直接検索する案と、Cosmos DB に利用者別フィードを作る案を比較せよ。どんな条件なら後者を採用するか。
2. 取引の更新からフィードへの反映までの流れを示せ。Azure SQL の更新とイベント送信の間で障害が起きた場合も考えよ。
3. Cosmos DB にフィードを置く場合、文書の単位、パーティションキー、並び順に必要な項目を提案せよ。
4. 重複イベントと順序が前後したイベントを受け取っても、フィードが重複・逆戻りしない方法を述べよ。
5. フィードを全件作り直すとき、何を正本として読み、切替中の画面をどう扱うか。

## ヒント

- 表示のために複製したデータは、元の取引データから再生成できるとよい
- Event Hubs の大量ストリームが、この件数と処理目的に必要か考える
