# 問題: 配送状況の取り込み（中級）

## 背景

配送会社から「集荷」「配送中」「配達完了」の Webhook が届く。配送会社は応答が遅いと再送し、ときどき通知の順番も前後する。利用者の注文画面に現在の配送状況を表示したい。

## 要件

- Webhook の入口と注文画面は App Service。ピークは毎秒 200 件
- 受け付けた通知は失わず、受信後すぐに配送会社へ応答する
- 同じ通知の再送で履歴や現在状態を重複させない
- 「配達完了」の後に遅れた「配送中」が届いても、現在状態を戻さない
- 候補は Service Bus、Functions、Azure SQL、Cosmos DB、Blob Storage、Event Grid

## 設問

1. Webhook の受信から注文画面への反映までの流れを示せ。受信時に何を検証し、どの時点で応答するか。
2. 配送履歴と現在状態を RDB と NoSQL のどちらに置くか。画面の読み方と注文との関係を踏まえて選べ。
3. 通知 ID、配送 ID、配送会社が付けた時刻を使い、重複と順序の乱れをどう扱うか。
4. Service Bus と Functions で処理する場合、失敗したメッセージの再試行と調査方法を示せ。
5. この Webhook を Event Grid へ直接流す案について、業務処理の再試行要件と照らして採否を説明せよ。

## ヒント

- 到着順と、配送会社で実際に起きた順は違うことがある
- 配送会社へ成功応答を返す前に、どこまで確実に保存すべきか
