# 問題: 期限付き座席予約（中級）

## 背景

イベントの座席を10分間仮予約できる。利用者が期限内に支払えば確定し、支払わなければ席を戻す。人気イベントでは同じ席への操作が同時に届く。

## 要件

- 予約 API は App Service。1 イベント 5 万席、発売直後は毎秒 300 回の予約要求
- 1 席は同時に複数の有効な予約を持てない
- 支払確定と予約失効が同時に走っても、どちらか一方の結果に決まる
- 失効処理は数分遅れてもよいが、期限後の支払は受け付けない
- 候補は Azure SQL、Cosmos DB、Service Bus のスケジュールメッセージ、Functions、Container Apps Jobs

## 設問

1. 座席、予約、支払状態をどこに保存するか。RDB と NoSQL を比較し、一意性をどこで保証するか。
2. 仮予約、支払確定、期限切れの状態遷移を示せ。同じ席への同時要求をどう処理するか。
3. 予約期限を知らせる方法として、スケジュールメッセージと定期的な期限検索を比較し、採用案を示せ。
4. 失効メッセージの重複・遅延や、支払確定との競合が起きたときの DB 更新条件を説明せよ。
5. 予約 DB への保存後に失効処理の登録が失敗した場合、取り残された予約をどう見つけるか。

## ヒント

- キューが時刻を知らせても、最終的な有効期限の判定は DB の状態と時刻で行える
- 「空席か確認してから予約を作る」だけでは同時要求に弱い
