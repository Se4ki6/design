# 問題: 工場設備の状態ダッシュボード（中級）

## 背景

工場の設備が温度と稼働状態を定期送信する。管理者は設備ごとの現在値を画面で見て、異常が続いた設備を調べたい。

## 要件

- 5 万台の設備が10秒ごとにデータを送る。画面の現在値は30秒以内に更新したい
- 直近 30 日の生データを保管し、判定ルール変更時に再処理できること
- 異常通知は設備ごとに抑制し、同じ異常を何度も通知しない
- 画面は App Service。候補は Event Hubs、Service Bus、Container Apps、Functions、Azure SQL、Cosmos DB、Blob Storage

## 設問

1. センサーデータの入口として Event Hubs と Service Bus を比較し、今回の送信量と再読込要件に合うものを選べ。
2. 受信から現在値の更新、異常通知、30 日保管までの流れを示せ。各処理を同じコンシューマにまとめるかも検討せよ。
3. 設備マスタ、現在値、生データ、異常履歴を RDB・NoSQL・Blob Storage のどこに置くか。主な読み方から理由を述べよ。
4. Container Apps と Functions をどの処理に使うか。連続して流れるデータと単発の通知で使い分けを説明せよ。
5. 同じ設備のデータが重複したり、遅れて届いたりした場合、現在値が古い値に戻らない方法を示せ。

## ヒント

- 現在値を読む処理と、生データを長期間読み直す処理では保存先が異なる
- 設備 ID ごとの順序を考えると、イベントの分割キーを決めやすい
