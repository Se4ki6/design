# 問題: 商品カタログの保存先選び（初級）

## 背景

小さな EC サイトの商品ページを作る。商品ごとに共通の価格・販売状態があり、衣服にはサイズ、家電には消費電力など、カテゴリごとに異なる属性がある。商品画像も表示する。

## 要件

- 商品は 2 万件。管理者は商品 ID で更新し、利用者はカテゴリ別に一覧・詳細を見る
- 価格と販売状態は正確に表示する。画像は最大 5 枚／商品
- アプリは App Service。候補は Azure SQL、Cosmos DB、Blob Storage
- 今後、カテゴリと属性が増える可能性がある

## 設問

1. 価格・販売状態、カテゴリ別属性、画像本体をどこに保存するか。RDB・NoSQL・Blob Storage の得意な点を使って説明せよ。
2. Azure SQL のみで作る案と、Cosmos DB を併用する案を比較せよ。今回の規模ではどちらを選ぶか。
3. 商品一覧と商品詳細の画面が、必要な情報をどう読み出すか示せ。
4. 価格変更時に古い価格が表示されないために、どのデータを正本として扱うか。

## ヒント

- 属性が変わりやすいだけで、必ず NoSQL が必要になるか
- 複数の保存先を使うと更新の手間も増える
