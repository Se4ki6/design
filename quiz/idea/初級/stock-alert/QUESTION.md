# 問題: 在庫更新と欠品通知（初級）

## 背景

小売店の管理画面で、担当者が商品の在庫数を更新する。在庫がしきい値を下回ったら、仕入担当者に通知する。

## 要件

- 管理画面は App Service。商品は 5 万件、更新はピーク時に毎分 100 件
- 商品 ID と現在庫は正確に管理し、商品 ID で検索できること
- 通知は数分遅れてよい。通知先の一時障害で在庫更新は止めない
- 同じ在庫更新をリトライしても、在庫数や通知を意図せず二重に変えない
- 候補は Azure SQL、Cosmos DB、Service Bus、Functions

## 設問

1. 在庫の正本を RDB と NoSQL のどちらに置くか。今回の更新・検索方法から理由を述べよ。
2. 管理画面から在庫更新を受け付け、通知するまでの流れを示せ。同期処理と非同期処理の境界はどこか。
3. Service Bus と Functions を使う場合、メッセージに何を入れ、Functions は何を行うか。
4. 通知先が停止した場合と、同じ通知メッセージが再配信された場合の扱いを説明せよ。

## ヒント

- 在庫が確定していない時点で通知を送ると何が起きるか
- 「通知を送ったか」を後から確認できる情報があるとよい
