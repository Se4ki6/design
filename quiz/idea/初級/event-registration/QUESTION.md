# 問題: イベント参加申込と確認メール（初級）

## 背景

地域イベントの申込サイトを作る。利用者は参加枠を申し込み、受付後に確認メールを受け取る。人気イベントでは、申込ボタンを連打する利用者もいる。

## 要件

- 申込 API は App Service。利用者は会員 ID でログイン済み。イベントごとに定員があり、ピーク時は毎分 200 件
- 1 会員は同じイベントに1回だけ申し込める
- 定員を超える受付はしない。メール送信は数分遅れてよい
- 申込一覧をイベント・受付日時・状態で確認できる
- 候補は Azure SQL、Cosmos DB、Service Bus、Functions、Blob Storage

## 設問

1. イベント、定員、申込情報を RDB と NoSQL のどちらに置くか。今回の一意性と定員管理から選べ。
2. 同じ人の二重申込と、同時申込による定員超過をどう防ぐか。DB で保証したい条件を示せ。
3. 申込確定から確認メール送信までの流れを示せ。Service Bus と Functions を使う理由も説明せよ。
4. 申込保存後にメール送信が失敗した場合、画面には何を表示し、運用担当者は何を確認するか。

## ヒント

- メールが届く前に、申込自体は成立してよいか
- 画面のボタン制御だけで同時申込を防げるか
