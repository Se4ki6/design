# 問題: 会員ポイント台帳と残高表示（上級）

## 背景

EC サイトで購入・キャンセル・キャンペーンに応じてポイントを付与する。利用者は現在残高をすぐに確認したい。イベントの再送や処理障害によって、ポイントが二重に付与されることは避けたい。

## 要件

- 注文 API は App Service。1 日 100 万件のポイント増減がある
- 残高と増減履歴を監査でき、誤処理は履歴を消さずに訂正する
- 残高画面は高頻度に読まれ、数秒の表示遅延は許容する
- キャンペーンルールの変更後、過去の対象注文を再計算できる
- 候補は Azure SQL、Cosmos DB、Service Bus、Functions、Container Apps Jobs、Blob Storage

## 設問

1. ポイント台帳、現在残高、キャンペーンルール、再計算用データをどこに置くか。RDB と NoSQL の正本・参照用データを区別せよ。
2. 同じ注文のイベントが重複しても二重付与しない、一意キーと DB 更新方法を示せ。キャンセルと訂正の記録方法も述べよ。
3. 台帳更新と、残高表示用データへの反映の間で障害が起きた場合、取りこぼしを防ぎ、遅れを検知する方法を設計せよ。
4. キャンペーンルール変更後に Container Apps Jobs などで再計算する場合、既存の台帳・残高をどう安全に更新するか。
5. 月末の台帳合計と表示残高に差が出たとき、原因を追えるデータと照合手順を示せ。

## ヒント

- 残高を直接上書きするだけでは、過去の付与理由を追えない
- 再計算時に、前回の付与を消すか、訂正仕訳を追加するかを決める
