# 問題: 保険請求書類の審査基盤（上級）

## 背景

利用者が事故報告と証憑画像を提出する。提出後、ウイルス検査と文書の読取を行い、担当者が内容を確認して承認・差戻しを決める。追加提出や再審査もある。

## 要件

- 受付 API と審査画面は App Service。1 件につき最大 20 ファイル、各 50 MB
- 提出された原本を保存し、検査前のファイルを担当者が開けないようにする
- 自動検査は 1 件あたり数分。失敗時は再試行し、手動確認へ切り替えられる
- 審査の決定と担当者の操作履歴は正確に残す。追加提出後は版を区別する
- 候補は Blob Storage、Event Grid、Service Bus、Functions、Container Apps Jobs、Azure SQL、Cosmos DB

## 設問

1. 受付、検査、読取、人手審査、承認・差戻しの状態遷移とデータの流れを示せ。各段階で誰が原本を閲覧できるかも説明せよ。
2. 請求、審査決定、抽出した文書情報、証憑原本を RDB・NoSQL・Blob Storage のどこへ置くか。正本と変更履歴を明示せよ。
3. Blob の作成通知から検査ジョブまでの経路を設計せよ。Event Grid から直接処理する案と Service Bus を挟む案を比較せよ。
4. Functions と Container Apps Jobs を検査・読取にどう使い分けるか。同じファイルのイベント再配信、ジョブ再試行、追加提出の版違いを扱え。
5. 読取結果と人の審査結果が食い違ったとき、どちらを優先するか。審査済み版の後から届いた自動処理結果で決定を上書きしない方法を示せ。
6. 検査失敗や長期滞留を見つける監視と、担当者が安全に再処理する手順を述べよ。

## ヒント

- ファイルが届いた事実と、安全に開ける状態になった事実は異なる
- 自動処理の結果には、対象ファイル ID と版を必ず結び付ける
