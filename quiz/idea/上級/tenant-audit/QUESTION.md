# 問題: マルチテナント SaaS の監査ログ（上級）

## 背景

企業向け SaaS で、設定変更やデータの閲覧・更新を監査ログに残す。各企業の管理者は自社分だけ検索でき、監査担当者は必要な期間をエクスポートできる。

## 要件

- アプリは App Service。全企業でピーク時に毎秒 15,000 件の監査イベントが発生
- 直近 30 日は利用者・操作種別・時刻で検索し、7 年間は原本を保管する
- 企業ごとに保持期間とエクスポート権限が異なる。他社ログは見せない
- ログが欠落した場合は検知し、収集停止中の管理操作をどう扱うか決める
- 候補は Event Hubs、Container Apps、Azure SQL、Cosmos DB、Blob Storage、Service Bus、Event Grid、Functions

## 設問

1. App Service から監査イベントを受け、検索用データと長期保管用原本に反映する流れを示せ。収集経路の障害時に管理操作を通すかも決めよ。
2. 直近検索、7 年保管、監査対象となる設定情報に、それぞれ RDB・NoSQL・Blob Storage をどう使うか。検索用データと原本の関係を明示せよ。
3. テナント間の閲覧分離と、1 社だけ大量に書き込む場合の影響をどう抑えるか。Cosmos DB を使うならパーティションキーも提案せよ。
4. 重複、欠落、時刻のずれをどう検知・扱うか。長期保管した原本から検索用データを再構築する手順を示せ。
5. 企業ごとのエクスポートと保存期限切れの削除を設計せよ。処理中や失敗時に他社データが混ざらない方法も述べよ。

## ヒント

- 検索しやすい形式と、長期間安く保管する形式は同じでなくてもよい
- テナント ID は認可だけでなく、データの分割や再処理にも関わる
