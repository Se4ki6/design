# 問題: 配送車両の位置追跡と遅延通知（上級）

## 背景

配送車両が現在位置を定期送信する。利用者には配送状況を、運行担当者には遅延の疑いを表示したい。通信が切れた車両は、復帰後に古い位置データをまとめて送ってくる。

## 要件

- 車両 20 万台、各車両が 5 秒ごとに位置を送る
- 現在位置は 30 秒程度で更新。遅延通知は重複させず、数分の遅れは許容する
- 位置履歴は 90 日保管し、到着予測ルール変更後に再集計できる
- 車両・配送先・配達完了の業務情報は正確に管理する
- 候補は Event Hubs、Service Bus、Container Apps、Functions、Azure SQL、Cosmos DB、Blob Storage、App Service

## 設問

1. 位置データと遅延通知で、Event Hubs と Service Bus をどう使い分けるか。イベントの分割キーと読み直し方法も述べよ。
2. 車両・配送先、現在位置、位置履歴、通知履歴を RDB・NoSQL・Blob Storage のどこに置くか。保持期間と読み方から判断せよ。
3. Container Apps 上の集計処理で、重複・遅延・順序の乱れをどう扱うか。過去の位置で現在地を上書きしない条件を示せ。
4. 到着予測ルールを変更したとき、90 日の位置履歴から再集計し、稼働中の速報値へどう切り替えるか。
5. Event Hubs の蓄積、コンシューマの遅れ、通知キューの滞留をどう監視し、どの障害で利用者画面へ何を表示するか。

## ヒント

- 車両端末の送信時刻と、サーバーへ届いた時刻は異なる
- 通知は業務上の処理であり、位置ログ全件と同じ経路で扱う必要はない
