# システムデザインのクイズ

## フォルダ構成

```
quiz/
  <トピック>/
    <問題名>/
      QUESTION.md   # 問題
      ANSWER.md     # 回答
      resource/     # 調査結果などのリソース
```

- トピックごとのサブフォルダに分ける
    - `system`: システム設計全般(キュー、スケーリング、分散システムなど)
    - `front`: フロントエンド(状態管理、レンダリング、パフォーマンスなど)
    - `db`: データベース(スキーマ、インデックス、シャーディング、トランザクションなど)
    - `api`: API設計(REST/GraphQL、バージョニング、認証認可など)
    - `infra`: インフラ・運用(クラウド構成、CI/CD、監視など)
    - `security`: セキュリティ
    - 該当しない場合は必要に応じてサブフォルダを追加する
- 各問題はトピック配下の問題サブフォルダ(`<トピック>/<問題名>/`)にまとめる

## ファイル

- `QUESTION.md` に問題を作成する
    - 先頭に以下のフロントマターを付ける
        - `summary`: 概要(1文)
        - `topic`: トピック(トピックフォルダ名と一致させる)
        - `level`: レベル(初級 / 中級 / 上級 / 中級〜上級 など)
- `ANSWER.md` にユーザーが回答を書く
    - 指示に応じて、AIが補助する
- `resource/` フォルダには、サービス情報などの調査結果を書く
    - 勝手に問題に特化した回答にしないこと
    - あくまで、ユーザーに質問された内容だけを記載する


- WEB 検索には `web-lookup` スキルがおすすめ
